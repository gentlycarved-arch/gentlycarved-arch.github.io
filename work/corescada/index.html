CoreSCADA

GeologicAI, 2026

CoreSCADA is the operator software for GeologicAI’s core scanning hardware. It brings the whole job into one interface: run a scan, check its quality, look back over records, and take care of the machine.

A mining company’s drill core is loaded into boxes on the scanner, which passes several sensors over it (photos, hyperspectral cameras, X-ray fluorescence and others) to turn physical rock into high-quality digital data. Operators in core shacks and labs run the machine for long shifts, often wearing gloves, and are usually technicians rather than software users.

The old workflow was spread across separate tools and relied on operators knowing the machine well. That made setup mistakes, missed quality issues and downtime more likely.

The design goals were:

  • Guide operators step by step instead of relying on memory.
  • Catch bad inputs before a scan starts, not after.
  • Make status readable at a glance from across the room.
  • Keep the interface calm and minimal, with details on demand.
  • Be accessible: status never relies on colour alone, and there are keyboard shortcuts for the high-volume review work.

I was the UI/UX designer: research with operators, flows and Figma designs, and front-end implementation in the production React/Next.js codebase.

Starting a scan is a five-step guided setup: project, drillhole, scan plan, box details, start. A wrong box name or depth range would mislabel the core data for good, so setup has to be hard to get wrong. Each step asks only for what’s needed, and Next explains what’s missing instead of failing silently. Once the scan starts, live progress shows each sensor pass.

A scan produces hundreds of images that someone must approve before the data is released. The gallery shows each image with its automated checks and quick Pass and Fail buttons. Several images can be decided together, and Focus review goes through them one at a time with keyboard shortcuts. A slow, error-prone sign-off becomes a fast, traceable review, and the scan only continues to its final stage once QC is complete.

The scan log is a searchable, filterable history of every scan, by project and date, with sortable columns. Supervisors and operators can find any past scan in seconds to check what was scanned, when, and with what result.

Machine events and errors live in one place, with type filters, search and full entry details. When something goes wrong, the operator can see what happened and when without calling an engineer or digging through raw log files.

Maintenance shows calibration status and the last reference scan. Starting a new reference scan is locked behind a safety checklist: it protects data quality, which depends on calibration, and it protects people, because the checklist must be confirmed before the machine moves.

Instruments shows the connection and state of every sensor on the scanner, with clear status and controls to recover one. It answers “is the machine healthy?” at a glance, and gives a direct way back when it isn’t.

All data shown is demo data, recorded on a local build with a simulated scanner.
